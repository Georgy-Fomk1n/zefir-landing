# Безопасность и персональные данные

## Токены и домены

- **Sanctum в режиме API-токенов** (Bearer), stateful-режим с cookie выключен (`config/sanctum.php: stateful = []`), CORS без credentials.
- Два вида токенов, которые **не взаимозаменяемы**:
  - `customer` — выдаётся на основном домене (`/api/auth/*`), срок `SANCTUM_CUSTOMER_TTL` (30 дней);
  - `staff` + `role:*` — только через `/api/staff/auth/login`, срок `SANCTUM_STAFF_TTL` (12 часов), при новом входе прошлый служебный токен удаляется, при смене ролей/блокировке — тоже.
- Маршруты кабинета требуют `abilities:customer`, служебные — `abilities:staff` и роль (`role:seller,admin` и т.д.). Права проверяются на бэкенде (middleware + Gates `view-order`, `deliver`).
- Сотрудник без роли customer не может войти в кабинет покупателя, покупатель — в служебный кабинет.
- 2FA для admin — TOTP (RFC 6238), секрет хранится зашифрованным (`encrypted` cast). [УТОЧНИТЬ метод 2FA]

### Где хранится токен на клиенте (компромисс)

| Клиент | Хранилище | Почему |
|---|---|---|
| Покупатель (основной домен) | `localStorage` | Токен-режим требует хранения в JS. Риск — кража при XSS. Меры: строгий CSP с хешами inline-скриптов, нет стороннего JS кроме отложенной Метрики, токен ограничен по сроку, выход отзывает его на сервере. |
| Сотрудник (штат) | `sessionStorage` | Закрытие вкладки = повторный вход; домен отдельный, CSP `script-src 'self'`. |
| Курьер (PWA, только роль courier) | `localStorage` | Смена не должна прерываться при сворачивании PWA; срок токена 12 часов. |

Альтернатива без хранения в JS — cookie-сессии Sanctum на общем родительском домене; требует `SESSION_DOMAIN`,
CSRF и не подходит под требование «API-токены», поэтому не выбрана.

## Защита API

- Валидация — FormRequest/`validate()` во всех контроллерах; цены и суммы всегда пересчитываются на сервере.
- Rate limiting: API 120/мин, вход 10/мин с IP и 5/мин на email, оформление 10/мин, геоподсказки 60/мин, деплой-хук 3/мин.
- IDOR: заказы покупателя (`view-order`), доставки курьера (`deliver`), абонементы проверяются по владельцу; тесты в `tests/Feature`.
- QR карт лояльности и абонементов — HMAC-SHA256 от `APP_KEY`, тип и срок жизни 5 минут; подделка без ключа невозможна, скриншот устаревает.
- Вебхуки оплаты: проверка подписи (Точка — JWT RS256 публичным ключом), идемпотентность по `webhook_events`.
- Деплой-хук: `hash_equals`, опциональный allowlist IP, 404 при любом отказе, выключатель в `.env`.
- Секреты только в `.env` сервера и GitHub Secrets; в репозитории — `.env.example` без значений.
- Заголовки: HSTS, `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`/`frame-ancestors`, CSP.
- `PAYMENT_PROVIDER=fake` на production блокируется при старте.

## Персональные данные (152-ФЗ)

- Согласие на обработку ПДн — обязательный чекбокс при регистрации и оформлении, время согласия хранится (`pd_consent_at`).
- Согласие на рассылку — отдельный необязательный чекбокс (`marketing_consent`).
- Курьер видит только данные для доставки; телефон — по политике `COURIER_PHONE_POLICY` (по умолчанию только в активной доставке) [УТОЧНИТЬ].
- Публичное отслеживание `/track/?t=` — без имени, телефона, адреса и сумм; ссылка действует 60 дней.
- Удаление аккаунта: обезличивание имени, email, телефона, адресов в заказах; удаление карт, токенов, корзины, избранного; отмена абонементов. Заказы остаются для учёта без ПДн.
- Фото вручения хранятся на диске `local` (вне публичной папки) [УТОЧНИТЬ срок хранения].
- Текст политики обработки ПДн — [УТОЧНИТЬ] у юриста; сейчас опубликована заглушка с реквизитами ИП.

`lighthouserc.json`, нарушение ломает CI. INP в лабораторном прогоне не измеряется; косвенный показатель — TBT ≈ 0.
Полевые данные (CrUX, Яндекс Метрика «Скорость загрузки») появятся после запуска.

Что дало результат:
- LCP-картинка без lazy, с `fetchpriority="high"` и `<link rel="preload" imagesrcset>` (главная, категория — первая карточка, товар);
- AVIF/WebP 400/600/800/1200 с `srcset`/`sizes`, явные `width`/`height` (CLS = 0);
- критический CSS инлайном (beasties), остальной CSS — в конце body; Inter self-host, subset, `font-display: swap`, preload кириллицы;
- видео — `preload="none"`, источники подставляются только у экрана; виджеты Яндекс Карт и Метрика — отложенно;
- кабинет, оформление, поиск и трекинг — отдельные чанки; служебные кабинеты — в отдельном приложении `/staff`.

Полные HTML-отчёты Lighthouse сохраняются артефактом `lighthouse-report` каждого запуска CI.

## SEO-проверки CI (`npm run seo:check`)

```
✓ SEO-проверка: 32 страниц, 25 индексируемых, ошибок нет
```

Проверяется: уникальные title (≤ 60) и description (≤ 160), ровно один H1, canonical = URL страницы,
OG-теги и существующая og:image, валидный JSON-LD (Product/Offer, BreadcrumbList, ItemList, FAQPage, WebSite),
хлебные крошки, `alt` и размеры у всех `<img>`, отсутствие битых внутренних ссылок, ссылок на служебные
разделы и старого домена, noindex на служебных страницах и его отсутствие на публичных, sitemap
(формат, lastmod, только существующие индексируемые URL, все индексируемые URL на месте), robots.txt.
Скрипт проверен на намеренно испорченной сборке — ловит каждую ошибку и завершается с кодом 1.

Разграничение, чтобы не было каннибализации:
- **«Наборы» vs «Подарки»**: наборы — товарная категория (канонические карточки `/catalog/nabory/…`);
  «Подарки» — подборка подарочных наборов со ссылками на те же канонические карточки, свой текст и интент «в подарок».
- **«Каталог» vs «Доставка и оплата»**: коммерческий запрос «купить с доставкой» → каталог; информационный
  «условия, стоимость доставки» → страница доставки.
- Страниц под районы Москвы нет и не будет: условия доставки по зонам — одна страница с реальной таблицей тарифов.

Источник истины для title/description/H1 контентных страниц — `frontend/src/content/pages.ts`;
товары и категории — SEO-поля в админке; переопределения контентных страниц — раздел «SEO» в админке.

## 2. Правила для редактора контента

- **Title** — до 60 символов, ключ в начале, «Москва» там, где уместно, бренд в конце, если влезает.
- **Description** — до 160 символов, живое предложение с выгодой и фактом (цена, вкус, срок), без перечня ключей.
- **H1** — один на страницу, может отличаться от title. H2–H3 — по смыслу, без пропуска уровней.
- **Slug** — латиница, через дефис, без дат и стоп-слов: `/catalog/vkusy/kofe/`. Смена slug меняет URL:
  старый адрес начнёт отдавать 404 — менять только при необходимости.
- **SEO-текст** — для людей: состав, вкус, повод, условия. Без переспама, без скрытого текста, без копий с других страниц.
- **Фото**: осмысленный `alt` («Корпусное пирожное со вкусом кофе в шоколадном корпусе»), имя файла латиницей.
- **Отзывы**: в разметку попадают только отзывы, оставленные на сайте и прошедшие модерацию.
  Отзывы из Яндекс Карт показываются виджетом и **не копируются** ни в текст, ни в JSON-LD.
- **noindex** ставить только у страниц, которые не должны быть в поиске (технические, дубли).
- Изменения в админке публикуются автоматически: цены — сразу, тексты — через ~5 минут.

## 3. Что реализовано и проверяется в CI

| Требование | Где |
|---|---|
| Пререндер всех публичных страниц: контент, мета, JSON-LD в исходном HTML | `vite-react-ssg`, `frontend/src/routes.tsx` |
| Настоящий 404 (без soft 404), fallback только для `/account/*` | `deploy/htaccess/public.htaccess`, `postbuild.mjs` |
| 301: http→https, www→без www, без слэша → со слэшем, `/index.html` → `/` | `.htaccess` |
| Уникальные title/description, один H1, canonical, OG/Twitter, хлебные крошки | `scripts/seo-check.mjs` |
| JSON-LD: Organization+Bakery, WebSite+SearchAction, Product+Offer, ItemList, BreadcrumbList, FAQPage | `frontend/src/seo/jsonld.ts` |
| Пагинация/фильтры: canonical на категорию, `noindex,follow` (meta + `X-Robots-Tag`) | `pages/catalog.tsx`, `.htaccess` |
| sitemap.xml с lastmod (индекс при >45 000 URL), robots.txt без служебных путей | `postbuild.mjs` |
| Lighthouse ≥ 90 / SEO ≥ 95, LCP ≤ 2,5 с, CLS ≤ 0,1 | `lighthouserc.json`, docs/lighthouse.md |
| IndexNow после деплоя production | `scripts/indexnow.mjs` |
| YML-фид Яндекс Товаров | `/feeds/yandex.yml` (генерируется при каждой сборке) |
| Self-host Inter, AVIF/WebP + srcset, preload LCP, lazy-видео и виджеты | `styles/fonts.css`, `media.tsx`, `scripts/media.mjs` |

## 4. Аналитика: цели Яндекс Метрики

Счётчик загружается отложенно (после согласия на cookie и первого взаимодействия или 4 с простоя),
только на production основного домена. На `штат.` Метрики нет.

| Цель | Когда |
|---|---|
| `click_telegram`, `click_flowwow`, `click_vk`, `click_max`, `click_yandex_maps` | клик по кнопке канала |
| `add_to_cart` | добавление в корзину |
| `checkout_start` | переход к оформлению |
| `checkout_complete` | заказ создан, переход к оплате |
| `register` | регистрация |
| `subscription_purchase` | оформление абонемента |

Цели создаются в интерфейсе Метрики как «JavaScript-событие» с этими идентификаторами.
GA4 — опционально [УТОЧНИТЬ]: переменная `GA4_ID` зарезервирована, код подключения не включён.
